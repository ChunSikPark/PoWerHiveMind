How your AI talks to PowerWorld

You talk to the agent in plain English. The agent reaches Simulator one of two ways.

The default: one live Python session

The agent writes Python with esapp, which drives Simulator through SimAuto. It opens the case, writes changes, solves, and reads every write back, because PowerWorld reports success on writes that did nothing.

Fast, scriptable, runs in parallel. Every demo uses it. Needs the SimAuto add-on, which is licensed separately.

Aux file integration: the agent reads what PowerWorld said

Turn on one setting and Simulator watches a folder. The agent writes an .aux script and drops it in. Simulator runs it and writes back the result CSVs and its own message log for that script: records read, control adjustments, every mismatch iteration, and whether the solve succeeded.

A SimAuto call hands back only an error string, so a silent failure stays silent. Here the agent reads the log line that explains it, and you keep a script you can read and re-run.

It's slower: a dialog has to stay open, so there's no batching, and it needs a recent Simulator build.

How it finds the answer

The agent never reads the whole kit. It turns your question into search terms, reads only the pages that match, and says so when no page covers it. Two illustrated walkthroughs, built on real pages and searches.
